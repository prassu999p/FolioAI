  <action>
Create `app/api/holdings/import-tradebook/route.ts` as a POST handler.

Request body (JSON):
```typescript
{
  holderId: string
  filename: string
  batchId: string  // UUID generated client-side
  rows: Array<{
    symbol: string; isin: string; trade_date: string; exchange: string
    trade_type: 'buy' | 'sell'; quantity: number; price: number; trade_id?: string
  }>
}
```

Route logic:
1. Auth check via `supabase.auth.getClaims()` — return 401 if unauthenticated
2. Zod validate the request body (holderId non-empty, rows non-empty array, each row matches ValidatedRow shape)
3. Verify the holderId belongs to this user's family (SELECT from holders WHERE id = holderId, then verify family belongs to user via RLS)
4. Insert into stock_transactions: map each row with `mapToStockTransactionInsert(row, holderId, batchId, filename)`. Upsert with `onConflict: 'holder_id,trade_id'` and `ignoreDuplicates: true`. Count how many were actually inserted (total minus duplicates).
5. Compute aggregated position from the rows just inserted (buy transactions only for net quantity and weighted avg price). For each unique (tradingsymbol, exchange) group: net_quantity = SUM(buy_qty) - SUM(sell_qty), weighted_avg_price = SUM(buy_qty * price) / SUM(buy_qty) for buy transactions only.
6. Upsert into stock_holdings with: `{ holder_id, tradingsymbol, exchange, isin, quantity: net_quantity, average_price: weighted_avg_price, last_price: null, pnl: null, source: 'tradebook', imported_at: now, batch_id, import_filename: filename }`. Conflict target: `holder_id,tradingsymbol,exchange`. Do NOT overwrite existing Zerodha holdings if source is 'zerodha' — use a conditional upsert that only updates rows where source = 'tradebook'.
7. Return JSON: `{ imported: number, skipped: number, batched: batchId }`

Error responses: 400 for validation failures, 401 for unauth, 500 for DB errors.

Use `(supabase as any)` for table operations per project pattern (postgrest-js v2.99.2 limitation with custom Database generics).
