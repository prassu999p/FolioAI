  <action>
    **components/analytics/sip-section.tsx** — Server Component:

    Props: `{ transactions: AnalyticsTransaction[] }`
    (Transactions are passed in from the parent holder page — no additional DB call needed)

    Implementation:
    1. Convert AnalyticsTransaction[] to FolioTransaction[] shape for detectActiveSIPs
    2. Call `detectActiveSIPs(folioTransactions)` from `@/lib/analytics/sip-detector`
    3. If result is empty array: return null (renders nothing — not even a wrapper div)
    4. For each SIPSummary: compute SIP XIRR using `computeXIRR(sip.sip_cashflows)` — add today's SIP holding value as terminal cashflow (need holdings data; if not available, show '—' for SIP XIRR)
    5. Render section:
       - Section header: "Active SIPs" (h2 or similar)
       - shadcn/ui Table with columns: Fund, Monthly Amount, Next Debit, SIP XIRR
       - Monthly Amount: formatINR(monthly_amount) + "/mo"
       - Next Debit: format date using date-fns format(next_debit_date, 'dd MMM yyyy')
       - SIP XIRR: (xirr * 100).toFixed(2) + "%" or '—'
       - font-mono for all numbers

    Props interface: `{ transactions: AnalyticsTransaction[]; holdingsForSipXirr?: HoldingRowWithAnalytics[] }`

    **app/api/allocation/route.ts** — GET and POST:

    GET /api/allocation?holderId=X:
    1. Auth via getClaims()
    2. Fetch from holder_allocation_targets WHERE holder_id = holderId
    3. Verify holder belongs to user's family (subquery check)
    4. Return { equity, debt, gold, international } or { equity: 0, debt: 0, gold: 0, international: 0 } if no row

    POST /api/allocation:
    Body: { holderId: string, equity: number, debt: number, gold: number, international: number }
    1. Auth via getClaims()
    2. Validate body with AllocationTargetSchema (sum ≤ 100)
    3. Verify holder belongs to user's family
    4. Upsert to holder_allocation_targets ON CONFLICT (holder_id) DO UPDATE
    5. Return 200 with saved allocation

    Use `supabase.from('holder_allocation_targets') as any` for write (established postgrest-js pattern).
    Return 400 for validation failures, 401 for unauthenticated, 403 for wrong family.
  </action>

    Props: `{ holderId: string; holdings: HoldingRowWithAnalytics[] }`

    1. Fetch current target from GET /api/allocation?holderId=X via server-side fetch (or direct Supabase query)
       Use direct Supabase query: `supabase.from('holder_allocation_targets').select(...).eq('holder_id', holderId).single()`
       If no row, default all to 0
    2. Compute current allocation from holdings:
       - For each holding: call `mapCategoryToAssetClass(holding.fund.category)` — but holdings from get_holder_holdings don't include category
       - NOTE: Need to include category in the holdings query. For Phase 2, accept that category may not be in HoldingRow. If category is missing, group all as 'equity'. Plan 06 will resolve this if needed by fetching funds table separately.

    3. Group current_value by asset class using mapCategoryToAssetClass
    4. Compute total_aum from sum of current_value
    5. Current allocation % per class = (class_value / total_aum) * 100
