```typescript
interface HolderWithAUM {
  id: string
  name: string
  pan: string
  role: string              // 'Primary Holder' | 'Joint Holder' | 'Minor'
  totalCurrentValue: number | null
  totalInvested: number
  oldestNavDate: string | null
  xirr: number | null       // per-holder XIRR
}
```

In the `Promise.all` map for each holder, after fetching holdings via `get_holder_holdings`:
1. Also call `get_holder_analytics_transactions` with `p_holder_id: holder.id`, `p_start_date: null`, `p_end_date: new Date().toISOString().split('T')[0]` — use `(supabase as any).rpc(...)` pattern (same as in holder page.tsx).
2. Convert AnalyticsTransaction[] to Transaction[] using the same `toHoldingTransaction` pattern from `app/(dashboard)/families/[familyId]/holders/[holderId]/page.tsx` (cast transaction_type with validTxTypes set).
3. Build per-holder cashflows:
   - outflowTypes = new Set(['purchase', 'sip', 'switch_in', 'dividend_reinvest'])
   - For each transaction: amount negative if outflow, positive if inflow
   - Append terminal cashflow: { amount: totalCurrentValue ?? 0, date: new Date() }
4. Call `computeXIRR(cashflows)` — assign result to `xirr` field on the returned HolderWithAUM.
5. Derive holder `role` from `holder.is_primary` (if true → 'Primary Holder') and `holder.pan_unmatched` (if true → 'Minor'). For all others → 'Joint Holder'. Fetch `is_primary` and `pan_unmatched` by adding those fields to the family select query: `holders(id, name, pan, is_primary, pan_unmatched)`.

Also compute family-level XIRR by aggregating ALL holders' transactions into one cashflow list and calling computeXIRR. If any holder fails to load transactions, familyXirr = null.

Compute asset allocation from all holders' holdings:
- Import `mapCategoryToAssetClass` from `@/lib/analytics/asset-class-mapper`
- For each holding across all holders, look up scheme_code in a funds query to get category, then map to asset class
- But to avoid N+1 on funds, fetch all distinct scheme_codes from the aggregated holdings in one query: `supabase.from('funds').select('scheme_code, category').in('scheme_code', [...new Set(allHoldings.map(h => h.scheme_code))])`
- Build allocation totals: { equity: number, debt: number, gold: number, international: number } in currency values
- Compute percentages from totalAUM for the donut SVG math

For "Top Performing Funds": query the 2 holdings with highest `current_value / total_invested - 1` ratio from allHoldings (absolute return as proxy for 1Y return since we do not have 1Y NAV series). Include scheme_name and category from funds map. If no holdings exist, skip section.

For "Recent Activity": query `transactions` table joined to `folios` and `holders` for this family, ordered by `transaction_date DESC`, limit 5. Shape each row into { type: 'sip' | 'cas_import', description: string, timestamp: string }. Use `supabase.from('transactions')` with a join through `folios!inner(holder_id, holders!inner(family_id))` filtered to `family_id = familyId`. If the query is too complex for the typed client, use `(supabase as any)`.

Keep existing formatINR utility. Keep existing `maskPAN` utility (still used by other pages that might import it, but it is not rendered in the new dashboard — just leave the function).
