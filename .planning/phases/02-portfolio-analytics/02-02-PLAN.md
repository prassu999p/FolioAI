## Critical Implementation Notes from Research

### XIRR Sign Convention (Pitfall 3)
- Purchases/SIPs = NEGATIVE cashflows (money leaving investor's pocket)
- Redemptions = POSITIVE cashflows
- Current portfolio value = POSITIVE terminal cashflow (as if selling today)
- DB stores amount as positive for all types — must negate purchases in buildPortfolioCashflows

### XIRR Null Guards (Pitfall 1)
- Return null if < 2 cashflows
- Return null if no positive AND no negative cashflows (needs both directions)
- Return null if current_value is null (NAV not synced)
- Return null if portfolio < 7 days old OR gain/loss within ±0.5% of cost

### Period-filtered XIRR (Pitfall 2)
For period-filtered XIRR: reconstruct cost basis — include all transactions before period start as a single synthetic invested-value cashflow on period start date.

### SIP Next Date (Pitfall 5)
Use date-fns `addMonths()` — NOT simple +30 days arithmetic.

### AllocationTargetSchema
Zod `.refine()` for sum ≤ 100. Allow partial allocation (sum < 100 = unclassified/cash).
